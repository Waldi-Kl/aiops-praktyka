Claude Code: każde wywołanie narzędzia przechodzi przez kilka bramek

Model tylko proponuje wywołanie narzędzia, a wykonuje je Claude Code. Po drodze są bramki: hook, reguły z settings.json i tryb uprawnień. Za nimi stoi sandbox systemu, a całość może siedzieć w kontenerze z ograniczoną rolą. CLAUDE.md nie jest żadną z tych bramek, tylko kontekstem dla modelu.

Droga jednego wywołania: Bash(cat .env)

  1. Model proponuje. Model nie uruchamia niczego sam. Zwraca prośbę „wywołaj Bash z cat .env”. CLAUDE.md działa tylko tu: może skłonić model, żeby nie prosił, ale nacisk w czacie wystarcza, żeby poprosił.
  2. Hook PreToolUse. Twój skrypt dostaje JSON z nazwą narzędzia i argumentami. exit 2 blokuje wywołanie przed regułami, także w bypassPermissions. Zgoda z hooka (allow) nie zdejmuje jednak deny ani ask z kroku 3.
  3. Reguły z settings.json. Deny wygrywa zawsze i w każdym trybie. Read(.env) łapie Read, Grep, cat, head, tail, sed. Nie złapie python3 -c "open('.env')" — to idzie dalej, do kroku 4.
  4. Tryb uprawnień. Rozstrzyga, gdy żadna reguła nie pasuje: default pyta człowieka, auto pyta klasyfikator, dontAsk odmawia, bypassPermissions puszcza. Komendy tylko do odczytu (cat, ls, grep) idą bez pytania w każdym trybie.
  5. Wykonanie. Narzędzie rusza. Hook PostToolUse może zapisać wywołanie do logu audytu.
  6. Sandbox. Bash i jego procesy potomne działają w sandboksie systemu (Seatbelt na macOS, bubblewrap na Linuksie). Tu python3 dostaje Operation not permitted na .env. Read, Edit i MCP sandbox nie obejmuje.

Co z tego wynika

Prośba to nie blokada

CLAUDE.md działa przed bramkami, w głowie modelu. W teście Sonnet po jednym zdaniu nacisku przeczytał .env i podał hasło.

Deny wygrywa ze wszystkim

Z allow, ze zgodą z hooka, z trybem bypassPermissions. Ale łapie tylko to, co Claude Code rozpozna jako odczyt pliku.

Hook to Twój kod

Umie warunki (namespace, gałąź, środowisko) i audyt. Błąd w skrypcie przepuszcza wywołanie, więc testuj go jak kod produkcyjny.

Kontener nie ufa niczemu

Tylko za tą granicą --dangerously-skip-permissions ma sens. Nie montuj do kontenera ~/.aws ani ~/.kube.
