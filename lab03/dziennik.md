## Sugestia AI, której nie wdrożono (wymóg SUKCES)

Przy generowaniu workflow agent (Claude Code) rozważał użycie `make build push SERVICES="orders-api payments worker web"` (bezpośrednie wywołanie istniejących targetów z `app/Makefile`) jako najprostszego sposobu reużycia komend z buildu. **Nie wdrożono tego** — wybrano `docker/build-push-action` z `cache-from/cache-to: type=gha` per serwis, bo pętla `make build`/`make push` nie ma żadnego mechanizmu cache między przebiegami CI (każdy `docker build` zaczyna się od zera), co nie spełniałoby wymogu "cache" z zadania. `docker/build-push-action` zachowuje te same build-args (`APP_VERSION`, `APP_VARIANT=stable`) i konwencję tagów co Makefile, tylko z realnym cachem warstw.

## Weryfikacja SHA akcji

Zamiast `git ls-remote` (sugerowane w README) użyto `gh api repos/<owner>/<repo>/git/refs/tags/<tag>` — równoważna metoda (oba odpytują GitHub, nie lokalny cache agenta), z dodatkowym rozwiązywaniem tagów anotowanych (`object.type == "tag"` → drugie zapytanie o commit SHA). Żaden SHA nie został wymyślony przez agenta — wszystkie odpytane na żywo przed wpisaniem do `ci.yml`.

## Wniosek ogólny

Cztery z pięciu napotkanych awarii (#2–#5) miały wspólne źródło: **niezgodność między tożsamością GitHub (`Waldi-Kl`) a loginem/namespace'em kursu (`waldemar`)**, na którym oparta jest cała resztowa infrastruktura (k8s namespace, rola IAM, prefiks ECR). Każda kolejna warstwa (trust policy → polityka IAM → nazewnictwo Dockera) ujawniała to samo źródłowe niedopasowanie od nowa, aż wszystkie zmienne (`K8S_NAMESPACE`, `AWS_ROLE_ARN`, `ECR_REGISTRY`) zostały ujednolicone na `waldemar`.
